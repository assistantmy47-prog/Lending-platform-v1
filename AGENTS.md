# Project working agreement

Read README.md, docs/HANDOVER.md, docs/requirements.md and the existing concept documents before editing.
Preserve the chronological, decision-led feed; do not replace it with a dashboard.
Use white/light surfaces, near-black text and deep gold #8A651F.
Keep scenario fixtures, workflow state and UI rendering in separate modules.
Maintain corrected role boundaries: Middle Office handles confirms, reconciliations,
internal reporting and payment-related information; Operations handles borrower servicing.
Never convert a case resolution into an active rule. Preserve approval dependencies.
All examples and sources must remain clearly illustrative. No live financial execution.
Use npm test and npm run build after workflow changes. Update HANDOVER for each milestone.
No external dependencies are required. Do not add a framework without a concrete need.
